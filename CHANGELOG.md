# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Android app (PWA + Trusted Web Activity)
- Made the existing frontend installable rather than building a React Native client. Measured the alternative first: `src/**/*.tsx` is 13,942 lines (3,621 of them vendored ShadCN) and only 1,877 lines of renderer-free logic could be shared, so ~88% of the UI investment would have been thrown away to reach an Android share sheet. Chrome reports zero installability errors and fires `beforeinstallprompt` on production.
- Added `src/app/manifest.ts` (`display: standalone`, `start_url: /runs`, `scope: /`, `id` pinned to `/` so a later `start_url` change cannot orphan installs) and a `viewport` export whose `themeColor` is a per-scheme array derived from the `--background` oklch tokens: `oklch(1 0 0)` → `#ffffff`, `oklch(0.141 0.005 285.823)` → `#09090b`. No `viewportFit: cover` — a TWA has no browser chrome and nothing in the app applies `env(safe-area-inset-*)`, so `cover` would put the shell header under the status bar.
- Cut a separate maskable icon rather than re-declaring the 512px one. Measured the brand mark's opaque bounding box at 394×353 and scaled it to 305×273 inside 512 — the largest that fits the 80%-diameter safe **circle**, which is the mask Android applies by default. Reusing the plain icon would let a circular mask clip the play triangle's corners.
- **The share target is the reason this exists.** `share_target` uses method GET, so a share arrives as ordinary query params that `src/app/share/page.tsx` reads from `searchParams` — no route handler and no redirect hop. Android share sheets routinely leave `url` empty and put the link in `text` wrapped in the sending app's own words, so all three params are swept and the first *supported* link wins.
- Validation and rejection copy both come from the shared `parseSourceUrl` and `relayProcessSchema`, so the share sheet and the New run dialog cannot disagree about what a supported link is. The refine's issue is selected by `code === "custom"` rather than `issues[0]`, because an empty share trips `.min(1)` first and would otherwise show Zod's internal "Too small: expected string to have >=1 characters".
- `/share` is deliberately **not** session-gated: `requireSession()` would bounce a signed-out user to `/login` and the shared link would be gone. The page renders for anyone, stashes the link in `localStorage` before it even checks auth, and resumes after sign-in. localStorage rather than sessionStorage because Google sign-in leaves the origin entirely and can return in a different tab context.
- Added a service worker at `public/sw.js` — served from the origin root because a worker's scope is its own directory, and a worker compiled out of `src/lib` would only ever control `/_next/static/service-worker/` without a `Service-Worker-Allowed` header. `/api/**` is network-only and never cached: run data is per-user, changes every 2s while a run is live, and the vault holds secrets. Verified against real traffic — zero `/api` entries in Cache Storage on production after exercising `auth/get-session`, `telemetry` and `relay/process`.
- Cache-first applies only to responses the server marks `immutable`, keyed off the header rather than a path prefix. Production Next stamps `public, max-age=31536000, immutable` on content-hashed output and `next dev` sends `no-cache`, so the worker caches real build assets and caches nothing in dev — where a cache-first hit on a rebuilt chunk would look like an app bug. No `NODE_ENV` read, which RULES.md forbids outside `src/config`.
- Added a self-contained `public/offline.html` navigation fallback, in both themes, from the app's own tokens converted from oklch. Static rather than a Next route on purpose: a rendered page's hashed CSS and JS chunk names cannot be precached, so it would render unstyled exactly when it matters. Verified by stopping the server, not by CDP offline emulation — which does not reach the worker's fetch context and silently passes.
- Wrapped the PWA as a Trusted Web Activity in `/mobile/twa` (not `/android` — `expo prebuild` owns that name). `space.k79.relay`, signed with a 4096-bit release key held outside the repo at `~/.relay-twa/`. The generated `AndroidManifest.xml` carries the `ACTION_SEND` intent-filter with `mimeType text/plain`; the web manifest alone never puts an app in the Android share sheet, and Bubblewrap derives that filter from `share_target` only at init/update time.
- `public/.well-known/assetlinks.json` serves the release key's SHA-256, generated by `bubblewrap fingerprint generateAssetLinks` rather than hand-written. Digital Asset Links verification returns `"linked": true` from Google's own resolver on the production domain, and the fingerprint matches the certificate embedded in the AAB.
- Auth needed no changes at all. A TWA is Chrome, not a WebView, so better-auth's cookie sessions work as-is and Google OAuth is permitted — Google blocks embedded WebViews, not TWAs.

### Sharing controls
- Added a **Run shared links immediately** toggle in Settings, default **off**. A share is one mis-tap away in any app and running on arrival costs a real download and a real LLM call, so by default `/share` shows the link and waits for "Run it".
- Fixed a duplicate-run bug: navigating **back** to `/share` re-queued the job, because the client-side submit guard is a ref that resets on remount. The page now looks up the newest run for the canonical URL on every render and offers "View that run" / "Run it again" instead of firing. Matching on the canonical URL means `/shorts/<id>`, `youtu.be/<id>` and a link carrying tracking params all collapse to the same row.

### Sources
- Accepted `youtu.be/<id>` short links and `youtube.com/watch?v=<id>` pages, which share sheets emit and which were previously rejected. A registry pattern is now a shape carrying its own host restriction, canonical form and optional query-param id, so `/watch?v=` works without a second YouTube entry — which would have created a second credential provider for one platform. The per-shape host guard is what keeps `youtube.com/mrbeast6000` rejected while `youtu.be/<11 chars>` is accepted, and the id from a query string is length-validated because it reaches yt-dlp's argv.
- `/shorts/` still canonicalises to `/shorts/`, keeping byte-identical the one URL form the proxy and `player_client` measurements in EGRESS_PROXY.md were taken against. The source label became "YouTube video", so `SUPPORTED_SOURCE_LABELS` and every rejection message updated themselves.
- **Known gap:** there is still no duration or filesize guard anywhere in the media path. That was harmless when only 60-second Shorts were reachable; a watch page can now be a three-hour podcast, and `config.queue.userSlotTtlMs` is 30 minutes, sized off a 328.7s worst case.

### Provider catalog
- `src/lib/providers.ts` imported React SVG components and carried Tailwind class strings, making the catalog renderer-coupled and unshareable with any future native client — and it was 333 lines, over the cap. Marks moved to `src/lib/provider-icons.ts` and accents to `src/lib/provider-styles.ts`; the catalog is 169 lines and imports only the media source registry. `Record<ProviderId, ...>` keying preserves the exhaustiveness check, so adding a provider is a compile error until it has a mark.
- Removed the `accent` field from `RAY_PROVIDERS` and `SOCIAL_PROVIDERS`. It was dead — every render site calls `providerAccent(id)` — so nothing rendered changes.
- Confirmed `src/lib/query/*`, `schemas.ts`, `media/sources.ts`, `runs.ts`, `run-status.ts` and `providers.ts` import nothing from `next/*`, `react-dom` or `src/components/**`, transitively across their full import closures.

### API auth
- Collapsed the identical two-line session guard that appeared in all 22 Hono module routes into `src/server/require-session.ts`. Two variants, because one would have broken production: `requireSession` returns 401 JSON, and `requireSessionOrRedirect` returns 302 to `/login` for the Ray OAuth start and callback, which the browser navigates to and where a 401 body would render as raw JSON in the address bar.
- Applied per module rather than by path in `route.ts`, because a module carrying its own `use("*", ...)` is fail-closed: a route added later is guarded by default, where a central path list is fail-open. Verified every endpoint 401s unauthenticated and works authenticated, with `/health` and `/telemetry` still public.

### Observability volume
- Stopped shipping request logs that answer no question to OpenObserve: Docker's `/health` probe (every 30s forever, 2,880 lines a day per container that say nothing `docker ps` does not), `/telemetry` (whose request body IS the browser's log payload, already shipped independently to the `relay_client` stream), and static assets (Next's proxy matcher only excluded `_next/static`, `_next/image` and `favicon.ico`, so the logo on every page render was being kept for 30 days). stdout and the log file still carry every line, so local debugging is unchanged.
- Stopped tracing the body of `GET /runs/:id/logs`. Its response is the run's log lines, the UI polls it every 2s while a run is live, and bodies are traced up to 8KB — so watching one run re-ingested the log store into itself. Status and duration are still recorded.
- Put the exclusion list in one dependency-free module rather than duplicating it, because two layers log requests and both have to agree: `src/proxy.ts` (Next's proxy, which runs in the edge runtime and cannot import the config module) and the Hono middleware. The proxy layer is the one that mattered — it posts to OpenObserve once per request with no batching, where the pino stream buffers 50 lines or 2 seconds.
- Diagnosed, but not fixed, that OpenObserve's read path returns 401 while ingest returns 200: logs are being stored and cannot be read back, so every run past the live window shows "No logs retained for this stage". `readRunLogsHistory` degrades to empty on any non-OK response by design, which is why a broken backend and an empty one look identical. Needs a credential with query rights; the probe table is in RUNBOOK §4.4.

### Code hygiene
- Made `bun run lint` pass. The failures were not formatting: two `@import` rules sat after a `@keyframes` block in `globals.css`, where CSS ignores them outright; the landing page keyed a duplicated marquee list on the array index and put `aria-label` on a bare `div`, whose `generic` role drops it. The marquee now builds a pre-keyed loop, and the workflow steps are an `<ol>` — the right element for a sequence, verified in the browser to render identically since preflight strips list markers.
- Brought every file back under the 250-line cap. `download.ts` was 372: the yt-dlp invocation and `scrubProxy` moved to `media/ytdlp.ts` and the info-JSON mapping to `media/info.ts`, leaving 172 lines of strategy. `logger.ts` was 254: the request-trace middleware moved to `observability/http-trace.ts`, leaving 189.
- 57 `useSortedClasses` warnings remain deliberately. Their autofix is classified unsafe because reordering can change which of two conflicting Tailwind utilities wins, so bulk-applying it without screenshots was not worth the risk.

### YouTube egress
- Routed YouTube fetches through a Cloudflare WARP egress, because YouTube refuses datacenter addresses and the deploy is a VPS. Measured from the production host against 12 real Shorts: 0/12 direct ("Sign in to confirm you're not a bot"), 11/12 through the proxy, 11/12 from a residential connection with byte-identical files. This closes the gap to residential rather than beating it. Opt-in is a `proxied` flag on the source registry resolved onto `ParsedSource` at parse time, so the download step decides by reading a boolean and still names no platform; YouTube only, Instagram stays direct.
- Treated `MEDIA_PROXY_URL` as a credential: yt-dlp echoes the proxy it was handed when it cannot reach it and that stderr reaches the user-visible `run.error`, so `scrubProxy` strips it at the single point stderr enters the program, `proxy` joined the logger's redaction words while the `proxied` boolean deliberately did not, and `bun run verify:proxy` pushes a canary password through five real failure shapes plus a log record.
- Moved the proxy from a standalone Coolify resource back into `docker-compose.yml` as the `warp` service. As a standalone resource it sat on Coolify's shared network while the app sat on its own, `--network` in Custom Docker Run Options is silently stripped, and the only thing making `socks5://warp:1080` resolve was a hand-run `docker network connect` that every redeploy of the proxy destroyed. It publishes no port (gost auto-detects HTTP as well as SOCKS5, so a published 1080 on a public VPS is an open relay), persists its device registration so the exit address survives a restart, and healthchecks the tunnel rather than the listener. Deliberately not in the worker's `depends_on`: only YouTube uses it, so gating the worker would stop Instagram ingestion whenever WARP is throttled.
- Rejected putting the app on Coolify's shared network instead — Dragonfly runs with an empty `requirepass`, so that would expose the job queue to every other container on the host.

### Media ingest reliability
- Bumped the pinned yt-dlp from `2026.03.17` to `2026.08.19`, which fixed a live outage rather than being hygiene: the old pin 403'd on the media fetch for roughly half of YouTube items — metadata resolved, then the CDN refused the stream. Those 403s reproduced from a residential connection too, which read as source-side and was written up as such; it was a stale extractor. A/B the version before concluding anything about a widespread 403.
- Classified a failed download on the most informative attempt rather than the last one. A YouTube fetch walks the default client then each configured fallback, and they do not fail in order of usefulness: a 403 from the default client followed by "Requested format is not available" from a later client was reported as an extractor problem, discarding the 403 that pointed at the stale pin. The ladder now runs against every attempt and the highest rung decides, with the patterns and their measurements split into `failure-patterns.ts` and the ladder into `classify.ts`.
- Made two classification guarantees structural instead of incidental: proxy-unreachable fires only for an attempt that actually used the proxy, and `SESSION_EXPIRED` requires that the attempt being classified supplied a cookie jar, recorded per attempt rather than read off the enclosing run.
- Stopped reporting a missing format as an expired session — "Requested format is not available" contains "not available" and fell into the login-shaped branch, telling users to reconnect a session that was working and burning a reject against a credential they had just refreshed.
- Stopped reporting a bot challenge as a dead session, for the same reason: a cookie jar cannot answer a challenge aimed at the server's address.
- Exhausted the player-client chain on a client-shaped failure, and picked clients that can actually serve our format selector — the previous list led with one that cannot satisfy `bestaudio/best` at all.

### Run logs
- Added a per-stage log stream to the run detail rail, collapsed by default and fetched only when expanded, so a page view that never opens a stage costs no log traffic.
- Split storage by lifetime rather than adding any: the live window is a capped, TTL'd list in Dragonfly, and once that expires the same lines are read back out of OpenObserve, which the logger already ships to. `source` tells the UI which it got, so an empty panel can say why it is empty. Neither path needed a migration.
- Redacted run log fields at the point they enter the live stream, because these lines are rendered in the product — a withheld value shows as the literal `[REDACTED]` rather than being silently dropped.

Chose `bg-card` over `bg-muted` by measuring the token values: the metadata pair is 4.39:1 on light `--muted`, under the 4.5 bar that applies at 11px, and 4.83:1 on light `--card`.

- Clamped the dialog grid's column track, not only its rows, and composed the shared Modal across the vault so dialog widths stopped going edge-to-edge.

### Task 4.4–4.6: Extraction, Grounding & Notion Publishing
- Seeded Recipe and Location system agents per user and added agent routing: requested agent → user agent → system agent → a synthesized schema for an unseen category, with the agent-builder writing the new agent's prompt.
- Added a database-backed, Redis-cached model catalog and prompt store; both revalidate on modification, and no model id or prompt is hardcoded.
- Validated every model response against the routed agent's JSON Schema with one repair retry that feeds the validation errors back, parsing through `best-effort-json-parser`.
- Replaced per-property evidence citations with transcript-and-caption grounding: each extracted claim is scored on content-word overlap against the source and flagged, never silently dropped.
- Rendered extractions to a structured document tree and published it into the Notion `Guides` hierarchy — category row with emoji, inline entries database, and the page itself — using `@notionhq/client`.
- Added a Prompts dashboard, a reusable Modal, `json-edit-react` JSON panels, explicit Clone semantics for system agents, and instaloader-backed Instagram ingestion.
- Fixed the extraction prompt dropping the post caption: it was accepted as an input but never sent to the model, despite the agent prompts instructing it to read the caption.

### Deployment
- Split the Dockerfile into `deps`/`builder`/`runtime` stages so build-only artefacts stay out of the shipped image, and pinned the base to the Bun version this repo is developed against (the floating `oven/bun:1` tag had moved to a different minor than local development).
- Fixed the `worker` service recompiling the entire Next.js app on every deploy: it omitted the `NEXT_PUBLIC_*` build args that `relay` passes, and those are baked into `ENV`, so its build never matched the cache. Measured 16.4s of duplicated compilation, now a 3s cache hit.
- Moved dependency installation above the build-arg block so bumping a public version string no longer reinstalls dependencies.
- Added an `init` process to the worker container so yt-dlp, ffmpeg and instaloader children are reaped, a loopback liveness endpoint so Coolify can report worker health, log rotation on every service, and a pinned Dragonfly image in place of `:latest`.
